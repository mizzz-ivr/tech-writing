# note記事テンプレート

> noteは技術の説明そのものより、経験・判断・価値観を中心にする。
> Qiita / Zennと同じ題材を扱う場合も、答える問いを変える。

## ファイル作成

新規note記事は次の形式で作る。

```text
articles/YYMMDD-<slug>/article.md
```

`YYMMDD` はJSTの執筆開始日。フォルダ名全体をArticle IDとして扱い、タイトル変更後も原則変更しない。詳細は `docs/ARTICLE_NAMING.md` を参照する。

## 仮タイトル

読者が「何についての体験・考察なのか」を一目で分かるタイトルにする。

## 書き出し

実際に起きたこと、最近考えるようになったこと、違和感などから始める。

「今回は○○について解説します」のような技術記事の導入には寄せすぎない。

## きっかけ

なぜこのテーマを考えるようになったのかを書く。

- 実際の開発
- 仕事
- 個人開発
- 学習
- OSS
- AI利用
- 社会や経済の変化

など、具体的な経験を置く。

## 以前はどう考えていたか

考えが変化した題材なら、以前の自分の認識を書く。

最初から正解を知っていたようには書かない。

## 実際にやってみて分かったこと

体験から得たものを書く。

技術的な内容が含まれる場合も、実装手順の網羅より「何が判断を変えたか」を中心にする。

## 今はどう考えているか

現時点の自分なりの結論を書く。

事実と意見を分け、将来変わる可能性がある考えは断定しすぎない。

## まだ答えが出ていないこと

必要なら、残っている疑問や迷いを書く。

綺麗に結論を作るためだけに不確実な部分を消さない。

## まとめ

本文の要約を繰り返すのではなく、読後に残したい考えを短く置く。

## 公開前チェック

- [ ] Qiita / Zennの既存記事と同一本文になっていない
- [ ] 自分の経験と一般論を混同していない
- [ ] 技術的事実はRepository / 公式Docs等で確認した
- [ ] 経済・制度・時事情報は公開時点の情報を確認した
- [ ] 顧客情報・業務上の機密・Secret・個人情報を含んでいない
- [ ] 他者や企業を不必要に特定・攻撃する内容になっていない
- [ ] 読者が無料部分だけでも一つの価値を得られる

## 有料化する場合の追加チェック

- [ ] 有料部分で何が得られるかを無料部分で明示できる
- [ ] テンプレート・判断基準・具体策など追加価値がある
- [ ] 結論を隠すだけの課金構成になっていない
- [ ] 自分の実体験・検証に基づかないノウハウを商品化していない
