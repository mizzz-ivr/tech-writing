## 結論

Jev、普通のチャットAIだと思って触るとかなり感覚が違いました。

文章を書いてもらうというより、

**「この状態なら、どれを選ぶ？」**
**「どれくらい危ない？」**
**「YESの確率は？」**

みたいな「判断」だけを任せるAIです。

今回は、まず簡単な例から始めて、最後は開発で使いそうな判断までいろいろ投げてみます。

> この記事は実測中のDraftです。結果・確率・レイテンシは実際にJev Playground/APIで確認した値だけを追記します。

## Jevって何？

Jevは、長い文章を生成することよりも、ソフトウェアから扱いやすい**構造化された判断**を返すことに寄せたモデルです。

基本形はかなりシンプルで、

```text
state
  ↓
Jev
  ↓
Choice / Score / Noul
```

という感じ。

今回特に面白そうだったのが、この3種類です。

| 種類 | ざっくり何をする？ |
| --- | --- |
| Choice | 候補から1つ選ぶ |
| Score | 段階で評価する |
| Noul | YES寄りかNO寄りかを確率で返す |

チャットAIに「理由も含めて説明して」と頼むのとは、かなり用途が違います。

## Noulって何？

もう1つ面白いのがNoulです。

YES / NOを文字列で返すというより、**YESである確率として扱える値**を返します。

## だんだん開発っぽいことを判断させる

ここからが本題です。

せっかくなので、普段の個人開発で実際にありそうなケースを投げてみます。


- 今日中
- 今週
- 保留

## ケース5：「完了しました」を本当に信じていい？

AIエージェントを使っていると、個人的にかなり気になる問題があります。

**「完了しました」と言っているけど、本当に完了してる？**

たとえば、

```json
{
  "objective": "Qiita記事を公開する",
  "completed_work": [
    "記事本文を書いた",
    "GitHubへcommitした"
  ],
  "verification": [],
  "known_gaps": [
    "Qiitaの公開URLは未確認"
  ]
}
```

これをJevのCompletion系判断に渡してみます。

個人的には、ここがかなり気になっています。

コードを書くAIとは別に、**「本当に終わったの？」だけを判断するAI**を置く構成です。

```text

   ├─ verify_more
   └─ incomplete
```

これが安定するなら、AIエージェントの最後のゲートとして面白そうです。

## 「生成AI」ではなく「判断API」と考えると分かりやすかった

触る前は、

> また新しいLLM？

くらいの感覚でした。

でもJevをチャットAIとして見ると、たぶん分かりにくいです。

文章を書かせない。

会話もしない。

ツールも実行しない。

**状態を渡して、判断だけ返してもらう。**

そう考えると役割がかなり見えました。

```text
LLM
→ 調査する
→ 考える
→ コードを書く
→ 説明する

Jev
→ 判断する
```

もちろん実際のシステムでは、こんなに綺麗に分かれるとは限りません。

ただ、「この処理、本当にLLMに文章を生成させる必要ある？」と考えるきっかけにはなりました。

## 使うなら、Jevの判断をそのまま権限にはしない

特に削除・決済・本番変更などの操作では、確率が高かったから即実行、にはしたくありません。

```text
Jevの判断
   ↓
アプリ側のルール
   ↓
必要なら人間承認
   ↓
実行
```

という形にします。

Jev自身のドキュメントでも、確率はシグナルとして扱い、認可そのものにはしない考え方が示されています。

この辺は「判断特化AI」だからこそ、実装側の責任範囲を意識した方がよさそうです。

## まとめ

Jevを触ってみて面白かったのは、AIに何かを**作らせる**のではなく、AIに**決めさせる**ことをAPIとして切り出しているところでした。

今回試したのは、

- Choiceで候補を選ぶ
- Scoreでリスクを評価する
- NoulでYES/NOの確率を見る
- Issueの優先順位を判断する
- AIエージェントの「完了」を再チェックする

という使い方です。

実際にアプリへ入れるなら、まずは低リスクな分類・ルーティング・レビュー要否判定あたりから試すのが扱いやすそうです。

そして個人的に一番試してみたいのは、

**AIエージェントが作業して、Jevが最後に「本当に終わった？」を判断する構成。**

生成するAIと、判断するAI。

この2つを分けると、AIを使ったアプリの作り方がちょっと変わるかもしれません。
