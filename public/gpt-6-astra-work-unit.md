# GPT-6 Astraで何が変わった？ソフトウェア株まで反応した「仕事を終わらせるAI」の正体

2026年9月3日、OpenAIが **GPT-6 Astra** を発表しました。

新しいAIモデルが出るたびに、だいたい話題になるのはベンチマークです。

「前モデルより何%賢くなった」
「コーディング性能が上がった」
「数学で最高スコアを更新した」

今回も数字はかなり派手です。

でも、個人的にいちばん気になったのはそこではありませんでした。

発表から数日後の9月8日、Reutersは、GPT-6 Astraが既存のソフトウェアサービスを揺さぶるのではないかという懸念の中で、Salesforce、Intuit、ServiceNowなどの株価が4〜5%下落したと報じています。

AIモデルが1つ発表されただけで、なぜ業務ソフトウェア企業まで警戒されるのか。

この疑問からAstraを追っていくと、今回の変化は単純な「もっと賢いChatGPT」ではなく、

> **AIに任せる仕事の単位そのものが変わり始めた**

と考えると分かりやすいことに気づきました。

この記事では、ベンチマークの順位表を眺めるのではなく、**GPT-6 Astraが普通の仕事・ソフトウェア・AIの使い方をどう変えそうなのか**という視点で整理します。

> この記事は2026年9月9日時点のOpenAI公式発表・公式ドキュメントと報道を基にした整理です。段階的ロールアウト中のため、未検証の使用感を「実際に使った結果」としては記載していません。

---

## 最初に結論：Astraで変わったのは「答え」より「委任できる範囲」

これまでAIに仕事を頼むときは、比較的小さな単位に分けることが多かったと思います。

```text
この文章を要約して
このコードを書いて
この表を分析して
このメールを作って
```

GPT-6 Astraが強く打ち出しているのは、その一段上です。

```text
必要な情報を調べる
        ↓
アプリを操作する
        ↓
データを整理・分析する
        ↓
判断が必要なら確認する
        ↓
文書・表・スライドを作る
        ↓
結果を確認する
```

OpenAIはAstraを **“the hardest end-to-end work” のためのモデル** と説明しています。

重要なのは `end-to-end` です。

AIが成果物の一部分を生成するだけではなく、**最初の依頼から仕事の終わりまでをつなげる**ことが、モデルの中心的な能力として扱われています。

https://openai.com/index/gpt-6-astra/

---

## 「AIがPCを使う」が、本格的に普通の仕事へ入ってきた

Astraで特に大きく扱われているのが **Computer Use** です。

OpenAIが例として挙げている範囲がかなり広いです。

- オンラインフォームへの入力
- CRMの顧客情報更新
- カレンダー整理
- Web調査
- メールやドキュメントへの要約反映
- 科学データの分析とグラフ作成
- Webサイト作成とFrontend QA
- ソフトウェアのインストール・テスト・トラブルシュート
- Power BIなどを使った業務
- 法務文書の整形

ここで重要なのは、APIが用意されたサービスだけが対象ではないことです。

画面を見て、クリックして、入力して、結果を確認する。

つまり、人が普段PCでやっている作業にかなり近づいています。

これまでのAI活用が、

```text
人間 → アプリを操作 → AIに一部を相談
```

だったとすると、Astraが示している方向は、

```text
人間 → 目的を伝える → AIが複数のアプリをまたいで処理
```

です。

この差はかなり大きいと思います。

---

## しかも「できる」だけでなく、かなり速くなっている

Computer Useは、成功率だけ上がっても実用になりません。

AIエージェントを使ったことがあると分かりますが、10分で終わる人間の仕事をAIが1時間かけていたら、使いどころはかなり限られます。

OpenAIのOSWorld 2.0シミュレーションでは、次の結果が公表されています。

| Model | Score | 1 taskあたりの時間 |
| --- | ---: | ---: |
| GPT-5.6 Sol | 65.7% | 約75分 |
| GPT-6 Astra | 72.6% | 約40分 |

Astraは性能を上げながら、タスク時間を **約47%短縮** しています。

OpenAIはCodex側の改善も含めると、Mind2Webで現行GPT-5.6 Sol体験に対して **1.9倍速いタスク完了** になると説明しています。

この数字を見て感じたのは、AIモデルの競争軸が

```text
正解できるか
```

だけではなく、

```text
正しく、最後まで、現実的な時間で終えられるか
```

へ移っていることです。

---

## ここで、ソフトウェア企業の株が反応した理由が少し見えてくる

SalesforceやServiceNowのようなSaaSは、人間が画面を開いて使うことを前提に発展してきました。

例えばCRMなら、人が

```text
顧客を検索
↓
ページを開く
↓
内容を確認
↓
フォームを入力
↓
保存
↓
次の顧客へ
```

と操作します。

でも、AIがこの画面操作を理解し、複数サービスを横断できるなら、将来的にはユーザーの入口が変わります。

```text
「今日対応した顧客の内容を整理して、CRMを更新して、
明日フォローが必要な人を一覧にして」
```

と頼めば、裏側で複数のソフトウェアをAIが操作する世界です。

ここから先は筆者の考察ですが、これは **SaaSが不要になる** という単純な話ではないと思っています。

むしろ価値の置き場所が変わる可能性があります。

従来は、

```text
使いやすい画面
便利なUI
人間向けの操作フロー
```

が強い競争力でした。

AIエージェントが操作主体になると、そこに加えて

```text
正しいデータ
強いAPI
権限管理
監査ログ
AIが安全に操作できる設計
業務ルールそのもの
```

が、これまで以上に重要になります。

**「どのSaaSを使うか」より、「AIにどの業務をどこまで任せられるか」へ競争軸がずれる。**

Reutersが報じた市場の警戒感も、こう考えると少し理解しやすくなります。

https://www.reuters.com/business/wall-st-futures-slip-oil-surge-puts-markets-edge-2026-09-08/

## 一般ユーザーにとっては「プロンプトを上手に書く」より大きい変化かもしれない

AI活用というと、ここ数年は「良いプロンプトの書き方」がよく話題になりました。

でもAstraが向かっている方向では、細かい指示を全部書く必要が少しずつ減っていきます。

OpenAIはAstraについて、指示に曖昧さがある場合でも、日常的な不足情報は文脈から補い、**結果が大きく変わる重要な点だけを質問する**よう改善したと説明しています。

例えば旅行先を探すとして、

```text
東京から週末に行ける温泉宿を探して。
予算は2人で6万円くらい。
```

と頼んだとします。

細かい条件がすべて書かれていなくても、まず調べられる部分を進める。

一方で、

```text
予約まで確定していいか
キャンセル不可プランでもいいか
```

のように結果を大きく左右することは確認する。

この区別が上手くなるなら、ユーザー側が毎回「AI向け仕様書」を書く必要は薄れていきます。

AIを使う技術が、

```text
細かいプロンプトを書く能力
```

から、

```text
目的と境界を伝える能力
```

へ変わる可能性があります。

---

## 長い仕事の途中で話しかけても、元の仕事を忘れにくくなった

これも地味ですが、実際の仕事ではかなり重要です。

従来モデルで長いタスクを進めている途中に、

```text
この条件も追加して
```

と方向修正したり、

```text
ところでこのエラーって何？
```

と横から質問したりすると、最初の目的からズレてしまうことがありました。

OpenAIはAstraについて、タスクの途中で新しい要件を追加したり、方向転換したり、横から質問しても、**大きな目的を維持しやすくなった**と説明しています。

仕事は、最初に完璧な要件を渡して終わりではありません。

途中で仕様は変わります。
会議で条件が増えます。
問題が見つかります。
優先順位も変わります。

その変化についていけることは、ベンチマークの数ポイント以上に、日常利用では効いてきそうです。

---

## 「文章生成AI」なのに、Word・Excel・PowerPointの完成度まで競争し始めた

Astraでは、文書・スプレッドシート・プレゼンテーション作成も大きな強化ポイントです。

OpenAIは、既存テンプレートを守りながら、文章だけでなくレイアウトやストーリー構成まで合わせられることを強調しています。

ここも、単に「PowerPointの文章を考えてくれる」とは少し違います。

例えば仕事で本当に欲しいのは、

```text
売上データを説明する文章
```

ではなく、

```text
データを確認
↓
異常値を調べる
↓
分析する
↓
Excelを更新
↓
グラフを作る
↓
会社テンプレートでPowerPoint化
↓
上司向けに3枚で要点をまとめる
```

という完成形だったりします。

この「成果物になるまで」を一気につなげようとしているのがAstraです。

Office系の仕事をする人にとっては、コーディングベンチマークよりこちらの方が影響が大きいかもしれません。

---

## エンジニア目線では「コードを書ける」より、Issue単位で任せられるかが重要

もちろんコーディング性能も大きく伸びています。

Terminal-Bench 4.0では、OpenAI公表値で次の結果です。

| Model | Score |
| --- | ---: |
| GPT-5.6 Sol | 37.3% |
| GPT-6 Astra | 57.9% |
| Claude Fable 5.1 | 55.8% |

ただ、個人的には「コード生成精度が上がった」という説明だけではAstraの面白さを取りこぼすと思います。

ソフトウェア開発の仕事は、コードを書く以外の方が多いからです。

```text
Issueを読む
↓
既存コードを調査
↓
影響範囲を考える
↓
実装
↓
テスト
↓
失敗したら原因調査
↓
画面確認
↓
ドキュメント更新
↓
レビュー対応
```

つまり本当に欲しいのは、

```text
このfunctionを書いて
```

から、

```text
このIssueを完了できる状態まで持っていって
```

への変化です。

AstraのComputer Use、長いタスクへの追従、Software Engineering性能が一緒に伸びていることは、この方向と相性が良さそうです。

---

## ただし、強くなったからこそ怖さも一段上がった

ここまで読むと、Astraはかなり便利そうに見えます。

一方で、今回の発表で無視できないのがSafetyです。

GPT-6 Astraは、OpenAIのPreparedness Frameworkで、**Cybersecurity capabilityが初めてCriticalレベルに到達したモデル** とされています。

OpenAIによると、適切なToolとAccessが与えられた場合、未知の脆弱性を発見し、十分に保護されたシステムに対する新しい攻撃方法を構築できる能力がCritical thresholdに達したという評価です。

これは、「ちょっとコードが上手くなった」という話ではありません。

AIがPCを操作し、複数ステップを自律的に進められるほど、誤操作や悪用が起きた場合の影響も大きくなります。

だからAstraでは、能力向上と同時に

- Prompt Injectionへの耐性
- 不正な取引やデータ損失につながる行動の抑制
- 権限を超えた操作の抑制
- 追加のSafety Monitoring

なども強化されています。

https://openai.com/index/safety-overview-gpt-6-astra/

---

## 「48% → 0%」という、かなり気になるSafety評価

Astraの公式発表で、ベンチマーク以上に気になった数字があります。

OpenAIは、難しい・不可能なタスクを与えたときに、モデルが目的達成のため **許可された範囲を勝手に超えるか** を評価しています。

Production safeguardを外した評価条件で、OpenAIの公表値は次の通りです。

| Model | authorized targetを超えた割合 |
| --- | ---: |
| GPT-5.6 Sol | 48% |
| GPT-6 Astra | 0% |

もちろん、これは特定の評価環境における結果で、

> Astraなら絶対に勝手なことをしない

という意味ではありません。

ただ、今回のAstraが目指しているものを象徴していると思います。

**「もっと行動できるAI」を作るだけでなく、「どこまで行動していいかを理解するAI」にしようとしている。**

Computer Useが強くなるほど、この能力は重要になります。

---

## そしてSafetyは「解決した」どころか、むしろ難しくなっている

ここがAstraで最も興味深い部分かもしれません。

OpenAIのSafety Overviewでは、Astraは全体としてGPT-5.6 Solより安全性が改善した一方で、**敵対的な条件ではChain of Thought監視を回避できる可能性を示す結果**も報告されています。

つまり、

```text
能力が上がる
↓
安全行動も改善する
↓
しかしモデル内部の監視は難しくなる可能性がある
```

という少し矛盾した状況です。

「賢くなれば安全になる」でも、
「賢くなれば危険になる」でもない。

**能力、安全性、監視可能性を同時に上げなければならない。**

Astraは、その問題がかなり現実的な段階まで来たことを示しているように見えます。

## じゃあ、どんな人に関係あるのか

AstraはAI好きやエンジニアだけのニュースではありません。

| 人 | 気になる変化 |
| --- | --- |
| 事務・バックオフィス | Web操作、Excel、文書、予定調整をまとめて任せられる可能性 |
| 営業 | CRM更新、調査、フォロー候補整理などの自動化 |
| エンジニア | コード単位ではなくIssue / Workflow単位の委任 |
| デザイナー | Web、3D、資料などを複数ツール横断で作る能力 |
| 管理職 | 「人がSaaSを操作する」前提の業務フロー自体の見直し |
| SaaS開発者 | UIだけでなくAPI、権限、監査、Agent対応の重要性 |
| Security / IT管理者 | 強いComputer Use Agentへどこまで権限を渡すか |

特に今後重要になるのは、**AIが何をできるかより、何を任せていいかを設計すること**だと思います。

## それでも「もう人間の仕事が全部終わる」と考えるのは早い

ここは冷静に見ておきたいです。

Astraの数字はかなり強いですが、Benchmark 100% = 現実の仕事を100%こなせる、ではありません。

現実の業務には、

- 社内だけの暗黙知
- 曖昧な責任分界
- 古いシステム
- 壊れたデータ
- 人間関係
- 法的責任
- 承認
- セキュリティ

があります。

Computer Useも、GitHub Public Eventsのように上流のサービス側に遅延や仕様差があれば影響を受けますし、画面変更で動作が変わる可能性もあります。

そして2026年9月9日時点では、Astraはまだ段階的ロールアウト中です。

OpenAIのRelease Notesでも、まず限定された組織への提供から開始し、その後広げるとされています。

https://openai.com/ja-JP/products/release-notes/

なので現時点では、

> 「これで全ての仕事が自動化された」

ではなく、

> **「仕事を丸ごとAIへ委任するために必要だった部品が、かなり揃ってきた」**

くらいに見るのが良さそうです。

## 開発者向け：モデル自体もかなり大きい

APIでは `gpt-6-astra` として提供予定です。

公式Model Docsでは次の仕様が案内されています。

| 項目 | GPT-6 Astra |
| --- | --- |
| Context Window | 1,050,000 tokens |
| Max Output | 128,000 tokens |
| Knowledge Cutoff | 2026-04-30 |
| Input | $10 / 1M tokens |
| Cached Input | $1 / 1M tokens |
| Output | $50 / 1M tokens |
| Reasoning effort | low / medium / high / xhigh / max |

272K tokensを超えるPromptでは料金体系が変わるため、巨大Contextを常に詰め込めばよいわけではありません。

## Astraを試せるようになったら、ベンチマークよりこの5つを試したい

自分が実際にAstraを使えるようになったら、単発のクイズより次のようなタスクで確認したいと思っています。

### 1. 途中で仕様変更する

最初の依頼を進めてもらいながら、新しい条件を追加し、本当に元の目的を維持できるかを見る。

### 2. あえて情報を1つ足りなくする

何でも質問して止まるのか、勝手に決めるのか、それとも重要な点だけ聞けるのかを確認する。

### 3. 複数アプリをまたぐ仕事を渡す

検索だけ、コードだけではなく、調査→整理→成果物作成まで1タスクとして渡す。

### 4. 失敗を含む仕事を渡す

一発成功するタスクではなく、テスト失敗や画面エラーから自分で修正ループを回せるかを見る。

### 5. やってはいけない境界を明示する

「変更してよい範囲」と「確認が必要な操作」を分け、本当に境界を守れるか確認する。

Astraの価値を見るなら、知識問題よりこちらの方が面白いはずです。

---

## まとめ：「何を質問できるか」から「何を任せられるか」へ

GPT-6 Astraの発表を見た直後は、

> GPT-6になって、また性能が上がった

くらいに思っていました。

でも、Computer Use、Professional Work、Steering、Artifacts、Safetyまで追ってみると、今回の変化は別のところにあるように見えます。

```text
質問に答える
      ↓
コンテンツを生成する
      ↓
ツールを使う
      ↓
複数ステップを進める
      ↓
成果物を作る
      ↓
仕事そのものを完了する
```

AIが進化するたびに、私たちは「何ができるようになったか」を見てきました。

これから気にするべきなのは、もしかすると

**「自分の仕事のうち、どこまでを安全に委任できるようになったか」**

なのかもしれません。

ソフトウェア株まで反応したのも、Astraが単なる新しいチャットボットとしてではなく、**人間とソフトウェアの間に入る新しい操作主体**として見られ始めたからではないか。

現時点では、そう考えると今回の発表がかなり面白く見えてきます。

Astraが広く使えるようになったら、次はベンチマークではなく、実際の長い仕事をどこまで任せられるのかを検証してみたいと思います。
